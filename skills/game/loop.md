# loop —— 脑：一局怎么推进

## 固定的四拍

```
1 看     game_shot            "我现在在哪个界面？"
2 判     读上一块的宫格        "目标达成了吗？界面变了吗？"
3 做     game_do(steps)       3~5 秒的动作块
4 收     看结果 → 回到 1
```

一次循环 ≈ 5–10 秒真实时间，其中我思考占大头。**这不是缺陷，是设计**：游戏里等一等，比乱按安全。

## 每块的决策只用三个问题

不要在一张截图上做深度分析。只问：

1. **还是同一个界面吗？**（是 → 继续；否 → 先搞清楚切到哪了）
2. **目标还在吗？**（怪/选项/按钮在不在）
3. **有弹窗/结算吗？**（有 → 立刻停手处理，别继续按）

三个都答完就出手，不要犹豫到画面又变了。

## 什么时候必须停手（不是可选项）

| 情况 | 动作 |
| --- | --- |
| 连续 3 块画面几乎没变化 | `game_stop`，然后问人 |
| 出现不认识的界面 / 弹窗 | 先 `game_shot` 读字，读不懂就停 |
| 角色血量可见地掉到很低 | 停，问人要不要继续 |
| 出现付费、确认购买、删除、绑定账号之类 | **立刻停**，交给人 |
| 你要按的键超过 5 秒才结束 | 拆成两块 |

## 节奏参考

- 菜单/对话：一块只做一个动作，`every` 可以放到 1500ms
- 战斗：一块 3–6 个动作（走位 + 攻击循环），`every` 800ms
- 加载/过场：`game_do` 只放一个 `wait`，帧多一点看它什么时候结束

## 自言自语（给旁边看的人）

这不是心里想，是**说出来的两行字**：每块动手前一行，收手后一行。

- 前：`第 3 块：剩一只，血见底 → 上去补两刀`
- 后：`打掉了。界面没变，继续。`

规矩：

- 只写**看到什么 + 要做什么**，不写推理过程、不复述工具参数
- 一行 20–40 字；别把宫格里每格都念一遍
- 出意外才展开写（"右边跳出个没见过的窗口，先停"）

理由很实在：这些字会进上下文。一关 30 块、每块一行就够读；写成小作文，跑到一半就开始忘前面的界面长什么样。

## 不要做的事

- 不要为了"稳"把同一个键连按 20 次
- 不要在没有看清界面的情况下盲按回车/空格（很多游戏用它确认）
- 不要一局结束就继续按，先确认是"结算"还是"下一关"
