# learning —— 学：打完怎么变成知识

知识**只有写进文件才算数**。对话会丢，文件不会。一局打完必做一次复盘，通常挑 1–3 条，不要什么都写。

## 写到哪里（按内容分流）

知识按**模式**组织：`games/<游戏>/modes/<模式>/`

| 你学到的是 | 写到 |
| --- | --- |
| 某个键在这个模式里干什么 | `controls.md` |
| 一个界面的长相/位置 | 模式 `SKILL.md` 的「界面」一节 |
| 一个模式的机制（规则、数值、克制关系） | 模式 `SKILL.md` |
| 小夏定的规则、操作技巧 | `rules.md` |
| 探针参数、判据 | `qte.md` |
| 一关的具体打法（敌人、编队、顺序） | `stages/<关卡>.md` |
| 通用的手感（这类游戏该怎么打） | 对应层的 `hands.md` / `loop.md` / `reading.md` |

**只往里加事实，不加感想。** "这怪很硬"没用；"这怪 2000 血，两段标记后才掉得动"才有用。

## 一局的复盘格式

```
## <关卡名>（<日期>）
- 目标：一句话
- 编队/准备：用了什么
- 动作块：能复用的那几块（贴 steps）
- 结果：S / 通关 / 失败 + 卡在哪
- 新学到：1~3 条，带证据（"第 3 块之后出现弹窗 X"）
```

## 升级规则

- 同一条经验在**两局**里都成立 → 才写进模式的 `SKILL.md`（一次可能是巧合）
- **单局经验只能进 `stages/`**，不许直接升级成通用知识
- 写进去之后**下一局要读它**，否则等于没写
- 发现旧内容不对 → 直接改，不要留着两种说法

## 可信度标记（2026-11-01 新增，必做）

每条知识必须能说清**它是怎么来的**。写的时候在句尾标一个：

| 标记 | 意思 |
| --- | --- |
| `[实测]` | 我真按下去、真看到结果了 |
| `[录像]` | 只看过视频，没亲手做 |
| `[小夏纠正]` | 她明确说过"你错了"——**优先级最高** |
| `[推测]` | 我推的，**没验证**。用之前先确认 |

不标 = 默认当 `[推测]` 处理。

**坏例子**：`反击 QTE 只有敌人用特定技能时才出现`
**好例子**：`反击 QTE 只有敌人用特定技能时才出现 [小夏纠正]`

## 一个事实只有一个家

同一个事实**只写一处**，别处只能**引用**，不许复述。

| 事实类型 | 家住哪 |
| --- | --- |
| 按键干什么 | `controls.md` |
| 界面长什么样 | 模式 `SKILL.md` |
| 模式机制 / 流程 | 模式 `SKILL.md` |
| 小夏的规则 / 操作技巧 | `rules.md` |
| 探针参数、判据 | `qte.md` |
| 某一关的具体打法 | `stages/` |

复述的后果是**改一处忘两处**——2026-11-01 就出过：策略文件里改了硬规则，
同一文件的旧模板还在教"双探针并联守 10 秒"，两者直接打架。

**改完之后必须搜一遍关键词**，确认没有残留的旧说法。

## 每月自查（发现问题就改，别攒着）

- [ ] 有没有同一句话出现在两个文件里？
- [ ] 有没有 `[推测]` 拖太久没去验证？
- [ ] 有没有标题/状态写着"未验证"但其实早就验证了？
- [ ] 文件开头描述的机制，和正文说的是一回事吗？

## 不要写

- 一次性的位置坐标（换个分辨率就废了；要写就写成"屏幕中部偏右"这种相对描述）
- 没验证过的推测（宁可留空，也别编）
- 大段攻略原文（skill 是索引，不是资料库）
