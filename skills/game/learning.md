# learning —— 学：打完怎么变成知识

知识**只有写进文件才算数**。对话会丢，文件不会。一局打完必做一次复盘，通常挑 1–3 条，不要什么都写。

## 写到哪里（按内容分流）

| 你学到的是 | 写到 |
| --- | --- |
| 某个键在这个游戏里干什么 | `games/<游戏>/controls.md` |
| 一个新界面的长相/位置 | `games/<游戏>/screens.md` |
| 一个模式的机制（规则、数值、克制关系） | `games/<游戏>/<模式>.md` |
| 一关的具体打法（敌人、编队、顺序） | `games/<游戏>/stages/<层>.md` |
| 通用的手感（这类游戏该怎么打） | 对应层的 `hands.md` / `loop.md` / `reading.md` |

**只往里加事实，不加感想。** "这怪很硬"没用；"这怪 2000 血，两段标记后才掉得动"才有用。

## 一局的复盘格式

```
## <关卡名>（<日期>）
- 目标：一句话
- 编队/准备：用了什么
- 动作块：能复用的那几块（贴 steps）
- 结果：S / 通关 / 失败 + 卡在哪
- 新学到：1~3 条，带证据（"第 3 块之后出现弹窗 X"）
```

## 升级规则

- 同一条经验在**两局**里都成立 → 才写进 skill（一次可能是巧合）
- 写进去之后**下一局要读它**，否则等于没写
- 发现旧内容不对 → 直接改，不要留着两种说法

## 不要写

- 一次性的位置坐标（换个分辨率就废了；要写就写成"屏幕中部偏右"这种相对描述）
- 没验证过的推测（宁可留空，也别编）
- 大段攻略原文（skill 是索引，不是资料库）
