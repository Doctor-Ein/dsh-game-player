# dsh-game-player

给模型一双眼睛和一只手，让它**真的能玩游戏**——但只发键鼠事件，和真人玩家等价。

| 半边 | 做什么 |
| --- | --- |
| `lib/index.js` | 宿主入口，注册 7 个 `game_*` 工具 |
| `lib/bridge.js` | 管常驻 `powershell.exe` 助手（JSON 行协议、自动重启） |
| `lib/helper.ps1` | 真干活的 Win32/GDI 侧：屏幕采集 + `SendInput` + 窗口枚举 |
| `lib/session.js` | armed 状态机、坐标换算、动作日志 |
| `lib/tools.js` | 工具定义（模型面） |

设计说明见仓库里的 [`docs/PLAN-GAME-PLAYER.md`](../../docs/PLAN-GAME-PLAYER.md)。

## 工具

| 工具 | 用途 |
| --- | --- |
| `game_setup` | 起助手、探环境、可选列窗口 / 修执行策略 |
| `game_arm` | 绑定窗口并解锁输入（`confirm` 必须回填真实标题） |
| `game_look` | 单帧截图（可裁区域） |
| `game_act` | **核心**：跑一段动作块，同时采样多帧，回一张编号宫格 |
| `game_watch` | 只观察不动手 |
| `game_stop` | 松开所有键 + 解除绑定 |
| `game_log` | 读本次会话的动作日志（复盘用） |

## 为什么是「动作块 + 宫格」

模型的思考轮次是秒级的，游戏里一次按键窗口是零点几秒。把「动作」和「观察」合成一次调用后：
助手在 1–5 秒内按真实速度把键打完，同时每秒抓一帧，最后只回一张 6 格宫格。
模型看到的是「我刚才那 5 秒到底发生了什么」，而不是两次调用之间丢掉的一整段。

## 安全

- **没有 armed 就没有手**：所有输入工具第一句都是 `requireArmed()`。
- **窗口锁**：绑定窗口不在前台就拒发输入（除非显式 `allowBackground`）。
- **F12 急停**：按键循环每 20 ms 查一次 `GetAsyncKeyState`，按下即松开全部并中止当前块。
- **预算**：单块 ≤ 60 步、单次 hold ≤ 30 s、样本帧 ≤ 12。
- **日志**：`%TEMP%\dsh-game-player\sessions\<时间>\log.jsonl`，可复盘。

不读游戏内存、不注入、不加速——这条边界是硬性的。

## 已知限制

1. **独占全屏抓不到**（GDI 采屏幕像素），请用无边框窗口 / 窗口化。
2. 鼠标相对移动受游戏 raw input 影响，需要按游戏做一次灵敏度标定（写进对应 skill）。
3. 仅 Windows。
